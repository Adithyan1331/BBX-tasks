# Written Answers

## What is a closure and when have you used one?

A closure is a function bundled with references to variables from the lexical scope where that function was created. The outer function can finish, but the inner function can still access those variables because JavaScript keeps the needed lexical environment alive. Closures are useful when state should remain private without introducing a global variable or a class. For example, a counter factory can keep a `count` variable inside its outer function and return an `increment` function. Callers can increment and read the count only through the functions the factory exposes. Closures also appear in callbacks, event handlers, and functions that customize behavior. In this assignment, `memoize` closes over its cache so later calls can reuse earlier results, and `once` closes over a flag and the first result so the wrapped function runs only once. The important detail is that a closure retains access to bindings, not a frozen copy of their values.

## Explain the event loop.

JavaScript runs synchronous code on a call stack. When the stack becomes empty, the event loop coordinates queued work so asynchronous operations can continue without blocking the main thread. A timer or network operation is handled by the runtime; its callback becomes eligible to run after the operation is complete and its delay or readiness condition is met. Promise reactions, including `.then` callbacks and code after an `await`, are queued as microtasks. After the current synchronous work finishes, JavaScript drains the microtask queue before starting the next task, such as a timer callback. That is why a resolved Promise callback normally runs before a `setTimeout` callback, even when the timer delay is zero. The loop does not make ordinary JavaScript computation parallel: a long-running synchronous function still occupies the thread and delays rendering and callbacks. In browsers, rendering is coordinated between task turns. Node.js has related event-loop phases, but the same stack and microtask ordering explains the examples here.

## How does `this` work?

For a regular function, `this` is generally determined by how the function is called, not where it was written. In `object.method()`, the object immediately before the dot is the receiver, so `this` refers to that object during the call. Calling the same function without a receiver gives different behavior: in strict mode `this` is `undefined`, while non-strict behavior may substitute the global object. `call`, `apply`, and `bind` can explicitly supply a receiver for regular functions. Arrow functions are different: they do not create their own `this`; they capture it lexically from the surrounding scope. Consequently, assigning an arrow function as an object property does not make the object its `this`. In the trap example, `reg()` returns the object's `n`, but `arrow()` uses the surrounding top-level `this`, so its optional property access produces `undefined` in Node.js. Optional chaining prevents an error when the base is nullish; it does not bind `this` to the object.
