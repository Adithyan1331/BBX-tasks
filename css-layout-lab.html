01STACKING CONTEXT

How can 9999 lose to 1?

A child’s z-index only competes inside its parent’s stacking context. The transformed parent is painted as one unit beneath its sibling.

THE FIXRaise the parent’s stacking level, or remove the context-creating property.

02SPECIFICITY

A class can’t outvote an ID.

An ID selector has greater specificity than a class, regardless of source order. Adding more class selectors is the wrong contest.

THE FIXUse a reusable class for styling; keep IDs for anchors and relationships.
✕ BEFORE · ID WINS
This class loses.

.notice { color: green }
✓ AFTER · CLASS SYSTEM
One class, clear intent.

THREE QUESTIONS, THREE STARTING POINTS FIELD NOTES

Keep these in your back pocket.

01 / THE BOX

Explain the box model.

Every element is a rectangular box made of content, padding, border, and margin. Content is the text or media inside. Padding adds breathing room between that content and the border; the border frames the padded area; margin creates space outside the border, between neighboring boxes. By default, a declared width applies only to the content, so padding and borders make the rendered box wider than expected. With box-sizing: border-box, the declared width includes content, padding, and border. That makes dimensions easier to reason about: a 20rem box stays 20rem wide, even when its padding changes. This predictable sizing reduces surprises.

02 / THE CASCADE

How does specificity work?

When multiple CSS declarations target the same property, the cascade first considers importance and origin, then selector specificity, then source order. Specificity is commonly compared as a tuple: IDs, classes/attributes/pseudo-classes, and elements/pseudo-elements. An ID outranks any number of classes; a class outranks any number of element selectors. If specificity ties, the later declaration wins. In practice, keep selectors intentionally simple, favor reusable classes for visual styling, and reserve IDs for unique page targets or accessibility relationships. This keeps the cascade understandable and avoids escalating selector weight—or reaching for !important—just to override earlier CSS. A small specificity budget scales much better.

03 / THE TOOL

When do you reach for Grid rather than Flexbox?

Reach for Grid when the layout has meaningful rows and columns, or when elements need to align across both axes: page shells, dashboards, galleries, and card collections are natural fits. Grid lets you define tracks and place items in relation to the whole layout. Reach for Flexbox when arranging items along one primary axis and distributing available space: a navigation bar, a button row, or a label paired with an input. They work well together. A page can use Grid for its large-scale structure, then Flexbox inside cards and controls. Choose by relationship, not habit. That keeps the layout intentional.
